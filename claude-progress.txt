## Session 237: Decision-Transcript Reconciliation System

### Summary
Designed and implemented a consensus-based system to link decisions (from minutes)

### Changes Made

1. **Fixed transcript.py** - Exposed `detect_agenda_items` parameter in `chunk_file()` method
   - Parameter was available in `chunk()` but not passed through from `chunk_file()`
   - Now agenda item detection runs by default when chunking transcripts

2. **Enhanced embeddings.py**:
   - Added `load_video_meeting_map()` utility to load video_id → meeting_date mapping
   - Updated `build_transcripts_index()` with `detect_agenda_items` and `video_meeting_map` parameters
   - Updated `_transcript_chunk_to_metadata()` to include `meeting_date` in chunk metadata

3. **Created reconciliation.py** - New module for decision-transcript linking:
   - `DecisionTranscriptReconciler` class with consensus approach
   - Combines structural matching (agenda_item) + semantic matching (embeddings)
   - When signals agree → high confidence; when disagree → flag anomaly
   - `EdgeCaseHandler` for consent calendar, out-of-order items, revisits, multi-item discussions
   - `ReconciliationResult` and `BatchReconciliationResult` for metrics

### Test Results
- Agenda detection: 275/285 chunks tagged with agenda_item for Nov 17 meeting
- Reconciliation: 37.5% decision coverage, 69.8% transcript coverage
- 6 agenda items detected: 4.a, 5.a, 6, 6.a, consent, public_hearing
- All 31 smoke tests pass

### Architecture Decision
Consensus approach vs fallback: Both structural and semantic signals contribute to 
confidence scoring rather than semantic being a fallback. Agreement bonus when signals 
align, penalty when they disagree. This enables both query enrichment and data validation.

- Write batch script to re-index all transcripts with new agenda detection
- Test semantic matching with embeddings client

### Key Findings
1. **Decision IDs**: Actual format `20251117-item-6a` differs from documented `city-san-rafael-2025-11-17-6a`
   - Join via metadata: `meeting_date` + `agenda_item`

2. **Chunk IDs**: Positional (`chunk-42`), not globally unique
   - Join via metadata: `agenda_item` field

3. **Transcript IDs**: Format `transcript-{video_id}-{chunk_index}`
   - Join via `video_url` LIKE or metadata

4. **Issue IDs**: Format `{jurisdiction}-scf-{source_id}` 
   - **Direct ID join** with SQLite `issues.id` (most reliable pattern)

5. **Municipal Code IDs**: Format `{jurisdiction}-muni-{chapter}-{section}` (future)

- ID patterns with code locations for all 5 corpus types
- SQLite join SQL examples
- Cross-corpus join patterns (decision↔transcript, decision↔chunk)
