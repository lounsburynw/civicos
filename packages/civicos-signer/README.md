# CivicOS Signer

Portable attestation signing service for organizations that issue CivicOS attestation codes.

If your organization (civic group, library, city office) has been granted issuer authority for a jurisdiction, this package lets you run your own signing service. You hold the private key. CivicOS never sees it.

## What This Does

When a resident redeems an attestation code your organization distributed, the CivicOS relay calls your signer to produce a cryptographically signed attestation event. This event proves your organization vouched for this person. The resident stores it in their browser and attaches it to every voice and comment they submit.

```
Resident redeems code → CivicOS relay → YOUR signer → signed attestation → resident
```

Your signer has two jobs:
1. Hold your organization's private key
2. Sign attestation events when the relay asks

That's it. No database, no state, no user data.

## Quick Start

### Prerequisites

- Python 3.11+
- A CivicOS relay operator who will register your organization

### Install

```bash
pip install civicos-signer[server]
```

Or with Docker (skip to [Docker](#docker)).

### 1. Generate Your Keypair

```bash
civicos-signer keygen \
  --jurisdiction city-san-rafael \
  --organization "Your Organization Name"
```

This creates `.env.signer` with your private key and a bearer token. **This file is secret.** It controls your organization's attestation authority.

Output:
```
Issuer public key: a1b2c3d4...
Bearer token: xYz123...

Share the PUBLIC KEY with CivicOS to register as a trusted issuer.
Share the BEARER TOKEN with CivicOS so their relay can authenticate.
NEVER share the private key.
```

### 2. Send Two Things to CivicOS

| What | Who gets it | Why |
|------|-------------|-----|
| **Public key** | CivicOS relay operator | Added to the trusted issuer registry for your jurisdiction |
| **Bearer token** | CivicOS relay operator | So the relay can authenticate when calling your signer |
| **Private key** | **NOBODY** | Stays in your `.env.signer` file, never leaves your server |

The CivicOS operator will tell you your issuer ID and confirm registration.

### 3. Start the Signer

```bash
civicos-signer serve
```

By default it reads `.env.signer` from the current directory and starts on port 8850.

To use a different config file:
```bash
civicos-signer serve --env-file /path/to/.env.signer
```

### 4. Register With the Relay

Once your signer is running at a public URL:

```bash
civicos-signer register \
  --relay-url https://civicos-api.modal.run \
  --signing-url https://your-signer.example.com \
  --relay-api-key YOUR_RELAY_API_KEY
```

To preview the registration payload without sending:
```bash
civicos-signer register \
  --relay-url https://civicos-api.modal.run \
  --signing-url https://your-signer.example.com \
  --dry-run
```

### 5. Verify It Works

From any machine:
```bash
curl https://your-signer.example.com/health
```

Expected:
```json
{
  "status": "ok",
  "issuer_pubkey": "a1b2c3d4...",
  "jurisdiction": "city-san-rafael",
  "organization": "Your Organization Name",
  "version": "0.1.0"
}
```

That's it. Your signer is live. When residents redeem codes your organization distributed, the CivicOS relay will call your signer to produce the attestation.

## Docker

If you don't want to install Python:

```bash
# Build
docker build -t civicos-signer packages/civicos-signer/

# Generate keypair first (writes to ./config/.env.signer)
mkdir -p config
docker run --rm -v $(pwd)/config:/config civicos-signer \
  civicos-signer keygen \
    --jurisdiction city-san-rafael \
    --organization "Your Organization" \
    -o /config/.env.signer

# Run
docker run -d \
  --name civicos-signer \
  -v $(pwd)/config:/config \
  -p 8850:8850 \
  civicos-signer
```

## Configuration Reference

All configuration is via environment variables (or the `.env.signer` file):

| Variable | Required | Description |
|----------|----------|-------------|
| `CIVICOS_SIGNER_PRIVATE_KEY` | Yes | Your issuer private key (64-char hex). Generated by `keygen`. |
| `CIVICOS_SIGNER_JURISDICTION` | Yes | Jurisdiction code (e.g., `city-san-rafael`) |
| `CIVICOS_SIGNER_ORGANIZATION` | Yes | Your organization name (e.g., `Canal Alliance`) |
| `CIVICOS_SIGNER_BEARER_TOKEN` | Yes | Shared secret with the CivicOS relay. Generated by `keygen`. |
| `CIVICOS_SIGNER_ALLOWED_TYPES` | No | Comma-separated attestation types (default: `physical`) |
| `CIVICOS_SIGNER_PORT` | No | Port to listen on (default: `8850`) |
| `CIVICOS_SIGNER_HOST` | No | Host to bind to (default: `0.0.0.0`) |

### Attestation Types

Your organization may be authorized for one or more attestation types:

| Type | Meaning | Example |
|------|---------|---------|
| `physical` | Resident attended an in-person event | Farmer's market, city council meeting |
| `community-vouched` | Resident vouched for by a trusted community member | Client of a social services organization |
| `mail` | Code delivered to a residential mailing address | City clerk's office mailing |

The `--allowed-types` flag in `keygen` sets which types your signer will accept. The relay also enforces this — even if your signer accepts a type, the relay will reject it if your issuer registration doesn't permit it.

## Endpoints

Your signer exposes three endpoints:

### `GET /health` (public)

Returns your issuer identity. No authentication required. Use this to verify your signer is running and to share your public key.

### `POST /sign` (authenticated)

Called by the CivicOS relay when a resident redeems one of your codes. Requires the bearer token in the `Authorization` header.

Request:
```json
{
  "subject_pubkey": "resident's public key (hex)",
  "jurisdiction": "city-san-rafael",
  "attestation_type": "physical",
  "code": "SR-2026-03-A7K9",
  "relay_timestamp": 1741520000
}
```

Response:
```json
{
  "attestation_event": {
    "id": "...",
    "pubkey": "your issuer pubkey",
    "created_at": 1741520000,
    "kind": 30850,
    "tags": [
      ["d", "attest:city-san-rafael:resident_pubkey"],
      ["p", "resident_pubkey"],
      ["j", "city-san-rafael"],
      ["type", "physical"]
    ],
    "content": "civicos:attestation:v1:city-san-rafael:physical:1741520000",
    "sig": "schnorr_signature"
  }
}
```

You should never need to call this endpoint yourself. The relay calls it automatically.

### `GET /audit` (authenticated)

Returns a log of all signing operations. Pubkeys and codes are truncated for privacy.

```json
{
  "entries": [
    {
      "timestamp": "2026-03-09T...",
      "subject_pubkey": "a1b2c3d4e5f6...",
      "code": "SR-2026-...",
      "attestation_type": "physical",
      "event_id": "9f8e7d6c5b4a..."
    }
  ],
  "total": 1
}
```

## Verifying Attestation Events

To verify a signed attestation event (e.g., one exported from the browser extension):

```bash
civicos-signer verify attestation.json
```

Output:
```
VALID attestation
  Issuer: a1b2c3d4e5f6...
  Subject: 9f8e7d6c5b4a...
  Jurisdiction: city-san-rafael
  Type: physical
```

## Security

### What your signer protects

Your private key is your organization's attestation authority. Anyone with the private key can sign attestations claiming your organization vouched for them. Protect it like a password to a bank account.

### What the bearer token protects

The bearer token authenticates the CivicOS relay to your signer. Without it, anyone could ask your signer to sign arbitrary attestations. Only share it with the relay operator.

### What happens if your private key is compromised

1. Contact the CivicOS relay operator immediately
2. They will remove your pubkey from the trusted issuer set
3. Generate a new keypair: `civicos-signer keygen ...`
4. Re-register with the new pubkey
5. Existing attestations signed by the old key become untrusted
6. Residents who were attested by your organization will need to re-attest

### What happens if the bearer token is compromised

1. Generate a new token (any random string works)
2. Update your `.env.signer` with the new token
3. Restart your signer
4. Send the new token to the relay operator

### Replay protection

The signer rejects signing requests with timestamps older than 60 seconds. This prevents replay attacks where an attacker captures a legitimate request and resubmits it later.

## Troubleshooting

### "Attestation type not allowed"

Your signer is configured with `CIVICOS_SIGNER_ALLOWED_TYPES=physical` but the relay sent a request with a different type. Either update your allowed types or check with the relay operator about which types your organization is authorized for.

### "Request too old (>60s)"

The relay's clock and your signer's clock are more than 60 seconds apart. Ensure both servers are using NTP for time synchronization.

### "Missing bearer token" or "Invalid bearer token"

The relay is sending the wrong token. Confirm with the relay operator that they have your current bearer token.

### Signer won't start

Check that all four required environment variables are set:
```bash
grep -c '=' .env.signer  # Should show at least 4 non-comment lines
```

Check that the private key is valid (64 hex characters):
```bash
grep PRIVATE_KEY .env.signer | cut -d= -f2 | wc -c  # Should show 65 (64 + newline)
```
